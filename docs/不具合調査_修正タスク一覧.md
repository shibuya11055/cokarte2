## 総評

既存テストは通っているが、以下の不具合は未カバーだった。
特に「削除処理の 500 化」「他ユーザー顧客情報の露出」「サーバー側バリデーション欠落」は優先的に直すべき。

## 優先度 High

### 1. 顧客削除がカルテ存在時に 500 で落ちる

- 根拠
  - `Client` に `has_many :client_records` はあるが `dependent` 指定がない
  - `app/models/client.rb:28`
  - 削除処理は例外考慮なしで `destroy` を実行している
  - `app/controllers/clients_controller.rb:63-66`
  - UI 上は通常操作として削除ボタンが出ている
  - `app/views/clients/show.html.erb:27`
- 再現
  - `rails runner` で `client_records` を持つ `Client#destroy!` を実行すると `ActiveRecord::InvalidForeignKey` を確認
- 影響
  - 顧客削除で 500 エラー
  - バグ報告として顕在化しやすい
- 修正タスク
  - `Client` に `dependent: :destroy` もしくは削除禁止の明示制御を入れる
  - `ClientsController#destroy` で失敗時のハンドリングを追加する
  - 「カルテがある顧客を削除したとき」の request spec を追加する

### 2. アカウント削除が既存顧客ありで 500 になる

- 根拠
  - `User` に `has_many :clients` はあるが `dependent` 指定がない
  - `app/models/user.rb:8`
  - UI にはアカウント削除ボタンがある
  - `app/views/users/registrations/edit.html.erb:39-41`
- 再現
  - `rails runner` で顧客を持つ `User#destroy!` を実行すると `ActiveRecord::InvalidForeignKey` を確認
- 影響
  - アカウント削除導線が実質的に壊れている
  - データ残骸や問い合わせの原因になる
- 修正タスク
  - `User` 側に削除方針を定義する
  - 方針候補
    - 関連データを cascade delete
    - 退会を論理削除化
    - 顧客が残っている間は退会不可にして説明を出す
  - 退会フローの request spec を追加する

### 3. カルテ作成/編集画面で他ユーザーの顧客名が見えてしまう

- 根拠
  - 顧客プルダウンが `Client.all` になっている
  - `app/views/client_records/new.html.erb:22-24`
  - `app/views/client_records/edit.html.erb:22-24`
- 影響
  - 他ユーザーの顧客氏名が UI 上で露出する
  - 登録時の所有権チェックは入っているが、閲覧漏えいは防げていない
- 修正タスク
  - `ClientRecordsController#new`, `#edit`, 失敗時再描画時に `@clients = current_user.clients.order(...)` を渡す
  - ビュー側は `@clients` のみを表示する
  - 「他ユーザーの顧客名がフォームに出ない」request/view spec を追加する

### 4. サーバー側バリデーションが不足しており、不正データを保存できる

- 根拠
  - `Client` は実質 `email` の一意性しか見ていない
  - `app/models/client.rb:30-34`
  - `ClientRecord` は写真検証しかない
  - `app/models/client_record.rb:25-49`
  - 画面上は `required` や `min: 0` があるが、これはブラウザ依存
  - `app/views/clients/new.html.erb:16-17`
  - `app/views/client_records/new.html.erb:28-29`
- 手動確認できた内容
  - `Client` に空の `first_name` / `last_name` と不正メール文字列を保存可能
  - `ClientRecord` に `visited_at: nil` と負の `amount` を保存可能
- 影響
  - データ品質が崩れる
  - 将来的に一覧・検索・集計・外部連携で不具合化する
- 修正タスク
  - `Client`
    - `first_name`, `last_name` の presence
    - 必要なら `email` format
  - `ClientRecord`
    - `visited_at` の presence
    - `amount` の numericality `greater_than_or_equal_to: 0`
  - request spec で「UI を経由しない不正パラメータ」が 422 になることを追加する

## 優先度 Medium

### 5. Stripe webhook が秘密鍵未設定時に fail-open になっている

- 根拠
  - `STRIPE_WEBHOOK_SECRET` が未設定でも JSON をそのまま受け入れる分岐がある
  - `app/controllers/stripe/webhooks_controller.rb:11-18`
- 影響
  - 本番設定ミス時に署名なし webhook を受理してしまう
  - 課金ステータス改ざんリスクがある
- 修正タスク
  - `test` 以外では secret 必須にする
  - secret 未設定時は起動時警告または 500/400 で fail closed にする
  - 「本番想定で secret 未設定時は受理しない」spec を追加する

### 6. 顧客一覧の「最近のカルテ」が `MAX(id)` ベースで、実際の最新来店を指さない可能性がある

- 根拠
  - 最新カルテ取得に `MAX(id)` を使っている
  - `app/controllers/clients_controller.rb:13-14`
  - 表示文言は「最近のカルテ」
  - `app/views/clients/index.html.erb:20,36-38`
- 影響
  - 過去日付のカルテを後から登録した場合に、一覧上の「最近」がずれる
  - サポート観点で「表示が間違っている」報告になりやすい
- 修正タスク
  - `visited_at DESC NULLS LAST, id DESC` ベースで最新 1 件を取るように変更する
  - backfill 登録ケースの request spec を追加する

### 7. 画像アップロード失敗時に部分更新が起きうる

- 根拠
  - 作成時はレコード保存後にファイルをアップロードしている
  - `app/controllers/client_records_controller.rb:54-56`
  - 更新時は既存画像 purge と新規 upload を同一 transaction ブロックに置いているが、外部ストレージ処理は DB transaction では巻き戻らない
  - `app/controllers/client_records_controller.rb:78-82`
- 想定される不具合
  - 作成は「カルテだけ保存されて写真が欠落」
  - 更新は「既存写真だけ消えて新規アップロード失敗」
- 修正タスク
  - 失敗時の補償処理を入れる
  - purge は新規 attach 成功後に実行する
  - ActiveStorage/Stripe を stub した異常系 spec を追加する

## 優先度 Low

### 8. `:unprocessable_entity` が Rails 8 / Rack で非推奨警告になっている

- 根拠
  - `bundle exec rspec` 実行時に複数回 warning を確認
  - 主な該当箇所
    - `app/controllers/clients_controller.rb`
    - `app/controllers/client_records_controller.rb`
    - `app/controllers/two_factor_controller.rb`
- 影響
  - 現時点では動作するが、将来の Rack 更新で壊れる可能性がある
- 修正タスク
  - `:unprocessable_content` へ置換する
  - 関連 spec の status expectation を維持確認する
